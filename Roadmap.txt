Project Overview

Project: OpenWrt Pi Controller
Repository: TheBestBMXer/openwrt-pi-assistant
Package: openwrt-pi-controller
Current Version: 0.3.5
Target: v1.0.0

OpenWrt Pi Controller is a Python-based application designed to provide a web interface for managing and monitoring an OpenWrt router from a Raspberry Pi.

The project is currently in active development. Local Debian package builds on the Raspberry Pi are the current development workflow. GitHub release packaging will be finalized as the project approaches v1.0.0.

Development Roadmap
1. OpenWrt Connection Layer

The next major development task is to implement a dedicated OpenWrt communication layer.

Recommended structure:

src/openwrt_controller/
├── app.py
├── config.py
├── database.py
├── logging_config.py
├── main.py
│
└── openwrt/
    ├── __init__.py
    ├── client.py
    ├── connection.py
    └── system.py


Responsibilities should be separated clearly.

Connection Layer

Responsible for:

SSH connection management
authentication
command execution
connection timeouts
connection status
SSH error handling
host-key verification
OpenWrt Client

Responsible for:

communicating with the router
executing supported OpenWrt operations
converting router responses into application-friendly data
System Information

Responsible for collecting information such as:

hostname
OpenWrt version
kernel version
uptime
system load
memory usage
storage information
network information

The router communication layer should be independently testable through mocks so that most tests do not require a live router.

2. Application Service Layer

Keep Flask routes focused on HTTP/web concerns.

Recommended architecture:

Web UI
   │
   ▼
Application/service layer
   │
   ▼
OpenWrt client
   │
   ▼
SSH connection
   │
   ▼
OpenWrt router


This separation will keep router operations independent from the web interface and make future functionality easier to test and extend.

3. Dashboard

Build a dashboard displaying useful router information.

Initial dashboard functionality should include:

router connection status
hostname
OpenWrt version
uptime
CPU/system load
memory usage
storage usage
network/interface status

The dashboard should provide clear visual status indicators and useful error information.

4. Router Management

Expand management functionality progressively.

Potential areas include:

services
network interfaces
DHCP
firewall
Wi-Fi
system information
router reboot operations

Each feature should be implemented through the OpenWrt client layer rather than directly inside Flask routes.

5. Configuration

Provide configuration for:

OpenWrt hostname/IP address
SSH port
SSH username
authentication settings
web application port
persistent data directory
application name

Configuration should support sensible defaults and environment/config-file overrides where appropriate.

6. Persistence

Continue using the existing persistent data architecture.

Persistent data should remain under:

/var/lib/openwrt-pi-controller


Future database changes should include migration support and tests covering upgrades.

7. Security

Security should be treated as a core v1 feature.

Important areas include:

web authentication
secure credential handling
CSRF protection
SSH host-key verification
least-privilege service execution
secure filesystem permissions
safe command execution
input validation

Router commands should never be constructed from unvalidated user input.

8. Packaging

Continue maintaining:

Debian package support
systemd integration
persistent-data preservation
service-account management
upgrade compatibility

Before v1.0.0, perform a clean installation and upgrade test on the Raspberry Pi using the generated .deb.
